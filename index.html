Refresh Opportunity Scoring for Search Content

A machine-learning approach to prioritizing content for refresh investigation using anonymized search-performance signals.

Abstract

Search-content teams need a practical way to identify which content should receive attention first without treating a model's prediction as proof of future performance. This study evaluates whether a machine-learning approach can improve the identification of initial refresh candidates compared with a simple rule-based baseline. The analysis uses anonymized FlyRank search-content data, excludes label-derived and future-window features, and uses a client-grouped validation design. Logistic Regression achieved an F1 score of 0.7193 compared with 0.3579 for the rule-based baseline, while Random Forest achieved 0.7190. The resulting model was used to produce a ranked review queue in which the highest-priority records were characterized by strong model scores and declining performance signals.

1. Research Question

Question

Can a machine-learning model identify content that should be prioritized for refresh review more effectively than a simple rule-based scoring system?

Decision supported

The analysis supports a content-prioritization decision: which pages should a content team investigate first when deciding where refresh effort may be warranted.

The system is intended to prioritize human attention. It is not intended to automatically decide which content must be refreshed or to establish that refreshing a page will improve search performance.

2. Data

The analysis uses the anonymized FlyRank ML Internship dataset. The data contains content-level search and performance signals, including measures related to visibility, clicks, impressions, CTR, position, content age, update recency, and performance trends.

Feature families

  • Content age and update recency
  • Search position
  • Impressions
  • Clicks and pageviews
  • CTR
  • Historical activity
  • Performance trend signals
  • Other non-label-derived numerical and categorical attributes

Excluded fields

Fields were excluded when they directly represented the target, were derived from the target or decision logic, represented future information, or created a risk of leakage.

Label-derived and rule-derived fields

  • is_initial_refresh_candidate
  • needs_indexing
  • is_quick_win
  • needs_ctr_fix
  • needs_engagement_fix
  • is_underperformer
  • is_declining
  • health_score
  • ai_opportunity

Future-window fields

  • future_clicks
  • future_ctr
  • next_30d_sessions

Identifiers

content_id was used only to identify records in recommendation outputs and was not used as a predictive feature. client_id was used for grouped validation and was not used as a predictive feature.

The published analysis does not expose client names, domains, URLs, private queries, credentials, or raw private exports.

3. Methodology

Prediction target

The prediction target is is_initial_refresh_candidate. The task is treated as a binary classification problem.

Feature preparation

Numerical and categorical features were handled separately. Numerical features were imputed and scaled. Categorical features were imputed and one-hot encoded, with unseen categories handled safely during transformation.

Preprocessing was implemented as part of the machine-learning pipeline so that transformations were learned from training data rather than from the held-out test data.

Leakage checks

A dedicated leakage investigation was performed before modeling. Three major sources were examined:

  1. Label-derived columns
  2. Future-window measurements
  3. Product and hand-written decision flags

These fields were excluded from the final predictive feature set.

Baseline

The Week-4 baseline was a rule-based scoring system using observable signals such as update recency and performance trend. It achieved an F1 score of 0.3579.

Validation design

A client-grouped split was used with StratifiedGroupKFold. Records belonging to the same client were kept within the same fold rather than being randomly distributed between training and testing data.

This design reduces the risk that the model benefits from seeing closely related records from the same client during training and then being evaluated on another record from that client.

Models

Logistic Regression and Random Forest were evaluated using the same validation design.

Logistic Regression was selected as the final model because it achieved the highest observed F1 score while remaining simpler than the tree-based alternative.

The machine-learning models substantially outperformed the rule-based baseline on the same held-out client-grouped test set. Logistic Regression produced the highest observed F1 score, although the difference from Random Forest was negligible.

The result supports choosing the simpler Logistic Regression model rather than selecting a more complex model solely because it is more sophisticated.

Feature interpretation

Feature-importance analysis for the Random Forest highlighted signals including average position, content age, impressions, days with impressions, historical impressions, and CTR.

These signals suggest that refresh-candidate identification is associated with a combination of search position, content age, visibility, and engagement rather than freshness alone.

Model quality check

An initially observed near-perfect Random Forest result was investigated before the final results were reported. The corrected Random Forest F1 was approximately 0.7190.

This investigation prevented an artificially inflated result from being presented as the final model performance.

5. Limitations & Honest Framing

This analysis is based on historical observational data. The relationships identified by the model should therefore be interpreted as associations rather than causal effects.

A high model score does not prove that refreshing a page will improve impressions, clicks, rankings, or engagement.

The available features cannot capture every short-term change or every reason why a page's search performance may change.

Factors such as editorial importance, business priorities, content quality, search intent, and strategic context may not be represented in the available data.

The model identifies pages worth investigating first; it does not determine which pages must be refreshed or prove that a refresh will improve search performance.

Action playbook

Investigate Decline Pages with high model priority and a declining performance trend should be investigated first. The investigation should determine whether the decline is persistent and whether a content intervention is appropriate.
Review Before Refreshing A high model score should not automatically trigger a refresh. Human review should consider information not available to the model before deciding on an intervention.
Monitor If the decline appears temporary or is explained by an external factor, monitoring may be more appropriate than changing the content.

What could make the recommendations wrong?

A recommendation can be wrong if the observed decline is temporary, if an external event explains the performance change, if important context is absent from the dataset, or if the historical relationship learned by the model does not apply to the current situation.
